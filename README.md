# LORD Security

**[Открыть приложение ↗](https://lord-security-nurali.onrender.com)**

**Образовательная веб-платформа о кибербезопасности с интерактивными инструментами, аккаунтами и AI-помощником.**

LORD объединяет материалы о цифровых рисках, локальную оценку сценариев, математическую лабораторию и учебную криптографию. Интерфейс поддерживает **English / Русский**: английский открывается по умолчанию, выбор языка сохраняется в браузере.

Проект использует HTML, CSS и JavaScript без сборки фронтенда, Flask для API, SQLite для локальных аккаунтов и опциональное удалённое хранилище Supabase. AI-запросы проходят через сервер в Groq.

## Возможности

| Раздел | Что реализовано | Требования |
| --- | --- | --- |
| Главная, решения, база знаний, о проекте, безопасность и данные | Информационные страницы, общая навигация и быстрый поиск | Статический сервер |
| Оценка киберриска | Локальный расчёт сценария по вероятности и влиянию | Браузер |
| Pifagor Lab | Формулы, переменные, графики, геометрические построения, производные, численные интегралы и оценка пределов, экспорт PDF | Доступ к внешним CDN |
| Cipher Terminal | Шифрование и расшифрование: Caesar, Vigenère, XOR, AES-256-GCM, RSA-OAEP; пояснения шагов | HTTPS или localhost для Web Crypto |
| Аккаунты | Регистрация, вход, выход и просмотр профиля | Flask и настроенное хранилище |
| AI chat | Ответы на вопросы по кибербезопасности на EN/RU | Flask и `LORD_GROQ_API_KEY` |

Это образовательный проект. Оценка риска не проводит сканирование или аудит системы, математические приближения не являются доказательством, а учебный шифратор не предназначен для обработки реальных секретов.

## Быстрый запуск

Все команды выполняются из корня репозитория.

```bash
git clone https://github.com/NuraliKuzhagaliev/lord.git
cd lord
```

### 1. Просмотр статических страниц

Нужен Node.js. Установка npm-пакетов и сборка не требуются.

```bash
node serve-static.js
```

Откройте **http://127.0.0.1:4173**. Работают информационные страницы и локальные инструменты. Аккаунты и AI API доступны при полном запуске ниже.

Если порт занят:

```powershell
# Windows PowerShell
$env:PORT = "4174"
node serve-static.js
```

```bash
# Linux / macOS
PORT=4174 node serve-static.js
```

### 2. Полный запуск с Flask

Рекомендуется Python 3.11+. Создайте собственное виртуальное окружение.

**Windows PowerShell:**

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r back/server/requirements.txt
.\.venv\Scripts\python.exe back/server/app.py
```

**Linux / macOS:**

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r back/server/requirements.txt
.venv/bin/python back/server/app.py
```

Откройте **http://127.0.0.1:5000**. Flask обслуживает и страницы, и API; отдельный статический сервер не нужен.

По умолчанию автоматически создаётся SQLite-файл `back/server/secure_db.sqlite`. Без AI-ключа сайт и аккаунты продолжают работать, а помощник сообщает, что не настроен.

Переменные задаются в окружении **до запуска**. Код не загружает `.env` автоматически. Например, для AI в PowerShell:

```powershell
$env:LORD_GROQ_API_KEY = "<your-groq-api-key>"
.\.venv\Scripts\python.exe back/server/app.py
```

## Конфигурация

| Переменная | Назначение / значение по умолчанию |
| --- | --- |
| `PORT` | Порт статического сервера, по умолчанию `4173`; также используется в команде Gunicorn на Render. Локальный `app.py` запускается на `5000`. |
| `LORD_SECRET_KEY` | Стабильный секрет подписания Flask-сессий. Если не задан, генерируется при старте процесса; после перезапуска сессии перестают действовать. Обязательно задайте для публичного сервера. |
| `LORD_HTTPS_ONLY` | `1` включает Secure для cookie. Используйте при HTTPS; для локального HTTP оставьте незаданным. |
| `LORD_PUBLIC_ORIGIN` | Разрешённый origin для изменяющих запросов, например `https://your-domain.example`. Затем код проверяет `RENDER_EXTERNAL_URL`, далее адрес самого запроса. |
| `LORD_DB_PATH` | Путь к локальному SQLite-файлу. Родительская папка должна существовать и быть доступна для записи. |
| `LORD_HOSTED` | При `1` регистрация, вход и профиль возвращают `503`, если удалённое хранилище не настроено. |
| `LORD_SUPABASE_URL` | URL проекта Supabase. |
| `LORD_SUPABASE_PUBLISHABLE_KEY` | Publishable key для серверных обращений к Data API. |
| `LORD_DB_GATE_KEY` | Секрет доступа к RPC аккаунтов; его SHA-256 должен быть записан в настройках базы. |
| `LORD_GROQ_API_KEY` | Серверный ключ Groq; включает AI-помощника. |
| `LORD_GROQ_MODEL` | Предпочтительная модель; по умолчанию `openai/gpt-oss-120b`. |

Удалённое хранилище включается, только когда заданы **все три** значения: `LORD_SUPABASE_URL`, `LORD_SUPABASE_PUBLISHABLE_KEY` и `LORD_DB_GATE_KEY`. В этом режиме SQLite не используется для аккаунтов.

## Публичный запуск на Render

В репозитории нет `render.yaml`: Web Service настраивается вручную.

- **Build command:** `pip install -r back/server/requirements.txt`
- **Start command:** `gunicorn --chdir back/server app:app --bind 0.0.0.0:$PORT`
- **Health check path:** `/healthz`

Задайте `LORD_HOSTED=1`, `LORD_HTTPS_ONLY=1`, стабильный `LORD_SECRET_KEY`, три переменные Supabase и, при необходимости, переменные Groq. Для собственного домена задайте `LORD_PUBLIC_ORIGIN` с точным HTTPS-origin без пути.

`/healthz` подтверждает ответ приложения и сообщает выбранный режим хранения. Он **не проверяет доступность базы или Groq**. Аналогично `/api/assistant/status` проверяет наличие AI-ключа, а не его валидность.

### Настройка удалённого хранилища аккаунтов

Авторизация реализована во Flask с bcrypt и cookie-сессиями. **Supabase Auth не используется**: Supabase хранит аккаунты в приватной схеме и предоставляет три RPC-функции.

1. Подготовьте отдельный проект Supabase с доступным Data API для схемы `public`.
2. Убедитесь, что расширение `pgcrypto` доступно в схеме `extensions`: SQL-функции используют `extensions.digest`.
3. Выполните [back/server/supabase_schema.sql](back/server/supabase_schema.sql).
4. Сгенерируйте случайный `LORD_DB_GATE_KEY` и запишите его SHA-256 в `lord_private.settings`. SQL-файл создаёт таблицу настроек, но **не заполняет её**.
5. Задайте исходный секрет и URL/publishable key в окружении сервера. Проверьте регистрацию, вход и профиль.

Получить случайный секрет можно локально:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

Для записи хеша выполните в SQL Editor, заменив placeholder на выбранный секрет:

```sql
insert into lord_private.settings (singleton, gate_hash)
values (
    true,
    pg_catalog.encode(extensions.digest('<LORD_DB_GATE_KEY>', 'sha256'), 'hex')
)
on conflict (singleton) do update
set gate_hash = excluded.gate_hash;
```

Не публикуйте заполненный SQL или секрет в репозитории. `LORD_DB_GATE_KEY` и Groq API key должны оставаться на сервере. При изменении gate key обновите и хеш в базе, и переменную сервера.

## API

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `GET` | `/healthz` | Ответ приложения и режим хранения |
| `POST` | `/api/register` | Создание аккаунта: `username`, `password` |
| `POST` | `/api/login` | Вход: `username`, `password` |
| `POST` | `/api/logout` | Завершение сессии |
| `GET` | `/api/profile` | Профиль текущего пользователя; требуется cookie-сессия |
| `GET` | `/api/assistant/status` | Наличие Groq-ключа в окружении |
| `POST` | `/api/assistant` | Вопрос: `message`, `language` (`en` / `ru`); ответ: `answer` |

POST-запросы должны иметь `Content-Type: application/json`; для выхода передайте `{}`. При наличии заголовка `Origin` сервер проверяет его совпадение с настроенным origin.

- Имя пользователя: 3–20 латинских букв, цифр или `_`.
- Пароль: минимум 12 символов, максимум 72 байта UTF-8.
- Срок постоянной сессии: 30 минут.
- AI-вопрос: максимум 1500 символов; каждый запрос отправляет один вопрос без истории переписки.
- AI endpoint не требует входа в аккаунт.
- Лимиты на IP в одном процессе: регистрация — 8 попыток/час; вход — 10/15 минут; AI — 15/15 минут.

AI сначала пробует модель, успешно использованную в текущем процессе, затем настроенную модель и встроенные варианты: `openai/gpt-oss-120b`, `qwen/qwen3.8-27b`, `openai/gpt-oss-20b`. Переход к следующей модели выполняется при HTTP `403` или `404`. Это список в коде, а не гарантия доступности моделей у провайдера.

## Разработка и проверки

Добавляйте инструменты в `front/homepage/tools-catalog.js`, включая `nameEn`, `subtitleEn` и `metaEn`. Русские исходные строки остаются в HTML; английские переводы новых строк и JS-сообщений добавляйте в `i18n.js`.

Запасная HTML-шапка генерируется скриптом ниже. При изменении её дизайна обновите шаблон в `scripts/sync-site-shell.py`; при изменении списка инструментов также обновите его `TOOLS`, поскольку он хранится отдельно от JS-каталога. Затем выполните:

```bash
python scripts/sync-site-shell.py
```

Проверки из корня проекта:

```bash
node scripts/check-links.js
node --check serve-static.js
node --check front/homepage/site.js
python -m py_compile back/server/app.py scripts/sync-site-shell.py
```

Проверка ссылок охватывает локальные HTML-ссылки и ресурсы; она не проверяет доступность внешних CDN или API. Автоматизированного набора функциональных тестов и CI workflow в текущем репозитории нет.

Для ручной проверки: откройте оба языка, выполните оценку риска, постройте график, проверьте шифрование/расшифрование, зарегистрируйтесь и войдите, откройте профиль и выйдите. С настроенным Groq-ключом отправьте вопрос на каждом языке.

## Обработка данных и ограничения

- Оценка риска, формулы и криптографические операции выполняются в браузере. Pifagor Lab загружает внешние библиотеки, включая MathLive, Math.js, Algebrite, JSXGraph и html2pdf.js.
- AI-вопрос передаётся через Flask внешнему провайдеру Groq. Не отправляйте пароли, ключи или конфиденциальные данные.
- Пароли аккаунтов хранятся как bcrypt-хеши. Сессия использует подписанную Flask cookie с `HttpOnly`, `SameSite=Lax` и опциональным `Secure`.
- AES использует PBKDF2/SHA-256, 250 000 итераций, случайные salt/IV и AES-256-GCM. RSA использует 2048-битные ключи, OAEP/SHA-256 и сообщения до 190 байт UTF-8. Caesar, Vigenère и повторяющийся XOR служат учебными примерами.
- Текущие ограничения запросов хранятся в памяти процесса и сбрасываются при перезапуске; они не объединяются между Gunicorn workers.
- Проверка Origin принимает запросы без этого заголовка. Её не следует описывать как полноценную универсальную CSRF-защиту.
- В текущей реализации нет восстановления пароля, подтверждения email, редактирования профиля и панели администратора. Поле `role` в базе само по себе не реализует разграничение доступа.

Перед эксплуатацией с реальными пользователями нужно проверить безопасность, настроить резервные копии и мониторинг, устойчивые лимиты запросов и защиту сессий для выбранного домена. Если ключ когда-либо попадал в публичный JavaScript или историю Git, отзовите его у провайдера: удаления из текущих файлов недостаточно.
